# Диагностика браузера экрана HDPlayer

Одна страница без внешних библиотек. Её открывают на плеере LED-экрана (HD-A3L и аналоги), чтобы увидеть версию браузера, User-Agent, базовые возможности и доступность `animal-park.by`.

Публикация: GitHub Pages, корень ветки `main`.

- Страница: https://salexvl.github.io/hdplayer-browser-test/
- Кадр: 896×576, три экрана, автосмена каждые 20 с
- Пауза: пробел или кнопка; `?page=1|2|3` закрепляет экран

## Почему GitHub Pages на экране работает, а animal-park.by даёт белый экран

Контроллер **HD-A3L** (прошивка вроде 2.12.8.0) показывает веб через старый встроенный браузер/WebView.

| Источник | Сертификат | Результат на LED |
|---|---|---|
| `salexvl.github.io` | Let's Encrypt → **ISRG Root X1** | Открывается |
| `animal-park.by` | GlobalSign → **Root R46** | Часто белый экран: корень R46 в старом WebView нет |

Дополнительно сам сайт парка — тяжёлый MODX: сотни килобайт HTML/CSS/JS, jQuery, reCAPTCHA, CDN. Даже при живом HTTPS это не страница для LED.

## Что делать

1. **Сразу:** HTML-программы для экрана держите на GitHub Pages (как эту диагностику).
2. **Проверка на экране:** откройте эту страницу → экран 3 «СЕТЬ». Если GitHub = ДА, а `animal-park.by` HTTPS = НЕТ — подтверждён отказ сертификата.
3. **Временный обход на хостинге парка:** каталог `http-pack/` залить в `/led/` по FTP и в HDPlayer указать `http://animal-park.by/led/` (не через ресурс MODX).
4. **Нормальный ремонт HTTPS:** на сервере animal-park.by выпустить сертификат Let's Encrypt (или иной с корнем, который есть в старом Android), либо добавить совместимую цепочку. После этого проверить снова экраном 3 диагностики.
